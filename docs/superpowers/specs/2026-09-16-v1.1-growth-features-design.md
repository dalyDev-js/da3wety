# Da3wety v1.1 — growth features design

Date: 2026-09-16. Status: approved in conversation; implementation plan follows.

## Goal

Turn the working v1 product into something that sells itself: a landing page with
plans, sign-in for hosts without Gmail, and invitation features Egyptian hosts ask
for (music, photo framing, countdown, calendar, wishes, gift, colour themes).

## Decisions (confirmed with the owner)

| Decision | Choice |
|---|---|
| Phone sign-in | Supabase Phone OTP through Twilio Verify. **SMS now**, WhatsApp channel later behind one env var. |
| Music source | Curated royalty-free catalogue seeded by us (~8 instrumentals). No host uploads. |
| Prices (EGP) | Basic **0**, Standard **499**, Premium **999**. |
| Tier gating | Music and themes free on all tiers; gallery (Standard+) and check-in (Premium) stay paid. |
| Image adjust | Crop/zoom/position baked into the uploaded file; no runtime crop data. |
| Extras in scope | Countdown + add to calendar, wishes wall + remind-pending, digital gift (نقوط), 4 colour themes. |
| Delivery order | E extras → C image crop → D music → A landing/legal → B phone auth (blocked on Twilio). |
| Tests | Playwright e2e suite is the first task; every sub-project ships with e2e coverage. |

## Sub-project E — invitation extras

### Countdown + add to calendar
- `Countdown` (client): days / hours / minutes to `event.startsAt`, ticking once a
  minute, hidden once the event has started. Rendered in the hero below the date
  after the reveal (same staggered fade, delay 3.1 s). Numbers use the event locale
  digits via next-intl.
- `AddToCalendar` (server): three links — Google (`calendar.google.com/render`),
  Outlook (`outlook.live.com/calendar/0/deeplink/compose`), and Apple/other via
  `GET /e/[slug]/event.ics` (Route Handler, `text/calendar`, `Content-Disposition:
  attachment`). Title = event title, location = venue name + address, description
  = invitation text, `DTSTART/DTEND` in UTC from Cairo times; `DTEND` defaults to
  start + 4 h when `endsAt` is null. Pure `buildIcs()` helper in `lib/calendar.ts`
  (unit-tested: escaping, folding, DST boundary).

### Wishes wall + remind pending
- Dashboard event overview gets a **wishes** section: RSVP messages with guest
  name, status and time, newest first, paginated at 50. Query in
  `db/queries/guests.ts` (`listWishes(eventId, page)`).
- Attendance/guests CSV export gains a `message` column.
- Guests page: pending guests get a **remind** action next to the WhatsApp share;
  message text is `Guests.reminderText` (distinct from the invite text), URL on its
  own line. "Copy all pending links" button copies `name — link` per line for hosts
  who forward manually.

### Digital gift (نقوط)
- `events.giftEnabled boolean default false`, `events.giftHandle text`,
  `events.giftNote text`. Edit form section "هدية رقمية": toggle, handle (InstaPay
  address or wallet number, `dir="ltr"`), optional note (max 200).
- Invitation body: section after venue with the note, the handle in a copy button,
  and a one-line hint. Never shown when disabled or handle empty.

### Colour themes
- `invitation-theme.ts` gains `THEMES: Record<ThemeId, InvitationTheme>` with
  `ivory` (current default), `sage`, `navy`, `noir`. Each theme defines paper,
  ink, muted, accent, gold, goldSoft **and** the envelope shades (flap, folds,
  liner), the foil tint and the confetti palette, so `EnvelopeGate`,
  `ScratchPhoto` and confetti read colours from CSS variables / a `theme` prop
  instead of literals.
- `events.theme theme_id enum default 'ivory'`. Edit form: four swatches with a
  live mini-preview (envelope + card); the invitation page passes the theme to
  `InvitationStage`.
- OG image keeps the theme's paper/ink colours.

## Sub-project C — image adjust (crop)

- `react-easy-crop` inside a dialog opened after the host picks a file. Fixed
  aspect per slot: cover **1.91:1** (link previews), reveal **5:4** (the oval).
  Drag to position, slider + pinch to zoom, rotate 90° buttons for sideways phone
  photos.
- On confirm, `cropToBlob(file, area, rotation)` draws the crop on a canvas at the
  target size (cover 1600×838, reveal 1600×1280 max), then the existing
  compress → reserve → signed upload path runs unchanged. The original `File` is
  kept in component state so "تعديل القص" re-opens the cropper without a new pick
  until the page is left.
- HEIC: converted with `heic-to` before cropping (already a dependency).
- No schema change.

## Sub-project D — music

- Table `tracks`: `id text pk` (slug), `title_ar`, `title_en`, `mood`
  (`romantic | classic | oud | upbeat`), `duration_seconds smallint`,
  `storage_path text`, `licence text`, `attribution text`, `sort_order`,
  `is_active`. Seeded from `db/seed-data.ts`; files uploaded once to
  `event-assets/music/<id>.mp3` (public bucket, 1-year cache). `CREDITS.md` lists
  every track's source and licence.
- `events.track_id text null references tracks(id)`.
- Edit form: "موسيقى الدعوة" list with play/pause preview (one `<audio>` element,
  switching `src`), duration, mood tag, and "بدون موسيقى". Preview uses
  `preload="none"`.
- Invitation: `InvitationAudio` (client) receives the track URL. Creates the
  `Audio` on the envelope tap (user gesture), `loop`, fades 0 → 0.6 over 6 s,
  pauses on `visibilitychange` hidden, resumes on visible unless muted. Floating
  mute/unmute button bottom-start, persisted in `sessionStorage`. Not started when
  `prefers-reduced-motion: reduce` or `navigator.connection.saveData`.
- The gate exposes an `onOpen` callback; the page wires it to the audio component
  through a small context so the server-rendered card stays untouched.

## Sub-project A — landing page, pricing, legal

- `/` (server component, Arabic default, locale toggle kept): hero (headline,
  sub, CTA "ابدأ مجانًا" → `/login`, secondary "شاهد مثالًا" → demo event link),
  phone-frame demo (an iframe of the seeded demo `/e/demo` event, lazy), "كيف
  تعمل" 3 steps, packages table with the seeded prices and the feature matrix
  (guests, gallery, moderation, QR check-in, music, themes), FAQ (6 items), footer
  with WhatsApp, privacy, terms.
- Prices come from the `packages` table (`priceEgp` seeded 0 / 499 / 999) so
  admin changes show up without a deploy.
- Dashboard: "ترقية الباقة" button on the event overview opens WhatsApp to
  `NEXT_PUBLIC_SUPPORT_WHATSAPP` with a pre-filled message containing the event
  title and short id; the operator assigns the tier in `/admin` as today.
- `/privacy`, `/terms`: static MDX-free server pages in both locales (content in
  `messages/*.json` under `Legal`), linked from the footer, login page and Google
  consent screen.
- Demo event: seeded by `scripts/seed-demo.mjs` under the operator's profile,
  slug `demo`, premium tier, real royalty-free couple photo, so the landing page
  and sales conversations always have a live example.

## Sub-project B — phone sign-in (SMS now, WhatsApp later)

- Supabase Auth Phone provider with **Twilio Verify**. Env: `AUTH_OTP_CHANNEL`
  (`sms` | `whatsapp`, default `sms`) read by the sign-in action; Twilio
  credentials live only in the Supabase dashboard.
- `/login`: tabs **Google** | **رقم الموبايل**. Phone tab: number input
  (`dir="ltr" inputMode="tel"`, normalised with `EgyptianPhone` → E.164) →
  `signInWithOtp({ phone, options: { channel } })` → 6-digit code input
  (`autocomplete="one-time-code"`) → `verifyOtp({ phone, token, type: "sms" })`
  (Supabase uses `sms` for both channels). Resend allowed after 60 s.
- Rate limits: 3 sends per phone per 15 min, 10 per IP per hour, via the existing
  `rate_limits` helper in a Server Action that wraps the send; verification
  attempts are limited by Supabase.
- Profiles: `profiles.phone text unique null`; the `handle_new_user` trigger copies
  `phone` and leaves `email` null. `requireHost()` unchanged. A user with no
  `full_name` is redirected to `/onboarding` (one field: display name) before the
  dashboard; `ADMIN_EMAILS` continues to grant admin by email only.
- Operator setup (documented in README): Twilio account → Verify service →
  Supabase Auth → Phone → Twilio Verify with SID/token/service SID; later, a
  WhatsApp sender approved by Meta + `AUTH_OTP_CHANNEL=whatsapp`.

## Cross-cutting

- Migration `0002_growth.sql`: `profiles.phone`, `tracks`, `events.track_id`,
  `events.theme`, `events.gift_*`, trigger update, package prices. RLS: `tracks`
  select for `authenticated`; nothing else exposed.
- Messages: new namespaces `Landing`, `Legal`, `Music`, `Theme`, `Gift`,
  `Calendar`; existing plural rules apply (unit test enforces).
- Tests
  - Unit: `buildIcs`, countdown math across a DST boundary, theme derivation,
    OTP phone normalisation, reminder text URL isolation.
  - E2E (Playwright, `tests/e2e`, dev-login against the local Supabase stack):
    login → create event → crop-upload a fixture image → pick theme + track →
    publish → open `/e/<slug>` → tap envelope → reveal photo (button) → RSVP →
    ticket → manual check-in → wishes visible → calendar `.ics` downloads. Phone
    OTP is tested with Supabase's test-OTP feature (fixed code for a test number).
- Performance budget: the invitation page must not grow by more than 15 KB gz of
  JS; audio and confetti load on interaction only.

## Out of scope

Host-uploaded music, per-guest seating, online payments, invitation delivery
from the platform, analytics beyond Vercel Analytics, multiple layouts.
